# Android APK / AAB Build Guide

This project already contains Expo Android identifiers, icons, and microphone permissions. The Android native project is generated by Expo Prebuild and is intentionally not committed to Git.

## Build profiles

- `preview-apk`: creates an installable APK for direct device testing using EAS internal distribution.
- `production-aab`: creates an Android App Bundle (AAB) intended for Google Play distribution.

The profiles are defined in `eas.json`.

## One-time EAS setup

Use Node.js 22 or later.

```bash
npm ci
npx eas-cli@latest login
npm run eas:init
```

The initialization command links this app to an Expo EAS project and writes `extra.eas.projectId` to the Expo app configuration. Review and commit that change before using the GitHub Actions workflow.

## Build an APK locally from the command line

```bash
npm ci
npm run typecheck
npm run build:android:apk
```

EAS will upload the project and build it in the cloud. When the build finishes, open the build URL printed by EAS, download the APK, and install it on an Android device.

To build a Play Store bundle instead:

```bash
npm run build:android:aab
```

Do not use the AAB profile for direct installation testing; use the APK profile.

## Optional GitHub Actions build

The workflow `.github/workflows/build-android-eas.yml` can be started manually:

1. Create an Expo access token from your Expo account.
2. In GitHub, open **Settings → Secrets and variables → Actions**.
3. Add a repository secret named `EXPO_TOKEN`.
4. Confirm that `app.json` contains the EAS `extra.eas.projectId` created by `eas init`.
5. Open **Actions → Build Android (EAS)**, select **Run workflow**, and choose `preview-apk` or `production-aab`.

The workflow waits for the cloud build to finish. The APK/AAB is stored in the EAS build page; this workflow does not copy the binary into the Git repository.

## Before sharing an APK

- Do not bundle a shared/private Gemini API key in `EXPO_PUBLIC_GEMINI_API_KEY`. Expo public environment variables are embedded in the client application.
- The app currently supports user-configured Gemini keys. Review how those keys are stored before distributing the app to other people; app-local SQLite is not a dedicated secrets vault.
- Verify that the optional local Whisper server URL is reachable from the phone. A computer's `localhost` address is not reachable as the computer from a physical phone.
- Test microphone permissions, speech recording, notifications, SQLite persistence, app restart, and AI fallback on at least one physical Android device.
- Keep Android package ID `com.daidai.app` stable after distributing builds. Changing it creates a different Android application identity.
- Back up important local vocabulary data before uninstalling or replacing test builds.

## Current limitations

An APK build profile and workflow are configuration, not proof that a successful APK has already been produced. The first build must still be run in an Expo account linked to this project and validated on a physical Android device.
